# MSDF-фігури: як користуватись — на всі випадки

Перевірено на пристрої 6 вересня 2026 (`TestScreen`, лабораторна збірка):
усі приклади нижче — з живого екрана, цифри draw calls — з дебаг-HUD.

## 0. Одна таблиця замість роздумів

| ситуація | інструмент | різкість | draw calls | пам'ять |
|---|---|---|---|---|
| одна фігура, будь-який розмір, без ефектів | `AMsdfImage(screen, msdf.x).apply { setSize(w, h) }` | будь-який розмір, як у Figma | 1 на актор | 0 |
| кнопка / панель, що РОЗТЯГУЄТЬСЯ | `ARoundRect` (кнопка) або растровий `.9.png` в атласі `_9_PATCH` (панель). **Не MSDF** | будь-який розмір, кути не пливуть | 1 на актор / батчиться | 0 / PNG |
| «як звичайна текстура» в `SpriteUtil`, фіксований розмір | `VfxTexture(w, h, base = msdf.x, shape = msdf.effect)` | тільки в **своєму** розмірі | батчиться як будь-яка текстура | `w×h×density²×4` |
| та сама, але в іншому розмірі | `.resized(w2, h2)` | у своєму розмірі | так само | ще одна текстура |
| з ефектом (блюр, світіння) | `VfxTexture(w, h, …, post = listOf(BlurEffect(r)), bleed = b).image()` | межі = фігура, ефект назовні | так само | `(w+2b)×(h+2b)×density²×4` |
| змінити ефект на льоту у всіх, хто його юзає | `tex.effect<BlurEffect>()?.radius = …` | — | 1 перемальовування FBO | — |

Ключ до всього: **MSDF-регіон — вектор, `VfxTexture` — растр.** Поки малюєш
регіон через msdf-шейдер, розмір вільний. Щойно запік у `VfxTexture` — це
картинка з пікселями, і всі закони PNG повертаються.

---

## 1. Вектор: одна фігура — `AMsdfImage`

```kotlin
val star = AMsdfImage(screen, msdf.star).apply {
    setSize(96f, 96f)
    color = Color.valueOf("ffd54a")                // тінт, як у Image
}
```

Це `VfxImage` з ефектом атласу, підставленим автоматично — «просто SVG-картинка».

Розмір міняй будь-коли — `setSize`, `Actions.sizeTo`, layout. Край перерахується
щокадру з поля. Це і є «SVG»: різко на 24 і на 320 з одного регіона 64 px.

Ціна: **окремий draw call на актор** (шейдер + юніформи ставляться в `draw()`).
Для одного-двох — байдуже. Для десятків — див. §2.

## 2. Вектор: багато фігур одним викликом — `AMsdfGroup`

```kotlin
val icons = AMsdfGroup(screen, gdxGame.assetsMsdf.effect).apply { setSize(360f, 130f) }
add(icons) { startToStart(margin = 0f); bottomToBottom(margin = 470f) }

icons.add(Image(msdf.star).apply  { setSize(16f, 16f) })                              { … }
icons.add(Image(msdf.star).apply  { setSize(96f, 96f); color = Color.valueOf("ff9f2e") }) { … }
icons.add(Image(msdf.heart).apply { setSize(40f, 40f) })                              { … }
```

Шейдер ставиться **раз на групу**, діти — звичайні `Image` з msdf-регіонами.
П'ять зірок різного розміру й кольору на екрані = один виклик.

Виміряно: увесь `TestScreen` v2 (13 фігур, серед них група з 5) — **draw 12**.
Попередній стенд з 5 `VfxImage` і 2 картинками — draw 14. Тобто група з п'яти
дешевша за п'ять окремих акторів, і різниця росте лінійно з кількістю.

Правила:
- діти — **тільки** `Image` з регіонами msdf-атласу цього ефекту. Звичайний PNG
  всередині пройде через msdf-шейдер і стане кашею;
- один стиль на групу; інший атлас або інші параметри — інша група;
- це `AConstraintLayout` — розкладай дітей через `add(actor) { … }` як звичайно;
- тінт і альфа — через `Image.color` кожної дитини, батч не рветься.

## 2а. Що НЕ робимо на MSDF

- **9-patch.** Відкинуто 7 вересня: кнопки — `ARoundRect`, розтяжні панелі — растрові
  `.9.png` в атласі `_9_PATCH` (`createPatch`, як `panel_coin`). Причини — `decisions.md`.
- **Коло з блюром «як у Figma».** `ACircle` / `CircleEffect` видалено. Різке коло —
  `msdf.circle`; світіння — PNG або `VfxTexture(base = msdf, post = [BlurEffect])` (§4).

## 3. Растр: «як звичайна текстура» — поруч із регіонами в `Msdf`

```kotlin
class Msdf {
    val star    = getRegion("star")                                        // вектор
    val star_48 = VfxTexture(48f, 48f, base = star, shape = effect)          // растр
}
// далі скрізь:
Image(gdxGame.assetsMsdf.star_48.region).apply { setSize(48f, 48f) }
```

`VfxTexture` один раз малює msdf-регіон через шейдер у власний FBO
(48 юнітів × density 3 = 144 px) і віддає стабільний `region`. Далі це
**звичайна текстура**: батчиться з іншими, тінтується, малюється хоч у ста
місцях — одна пам'ять, один виклик на всіх.

### Головне правило: малювати РІВНО в розмірі запікання

Перевірено на екрані:

| як намальовано | результат |
|---|---|
| `star_48` у `setSize(48, 48)` | різко — 1:1 |
| `star_48` у `setSize(128, 128)` | **мило** — ×2.7 розтяг, рівно як PNG |
| `star_48.resized(128f, 128f)` у `setSize(128, 128)` | різко — нова роздільність |

Менше за запечене — теж погано, але інакше: у FBO немає mipmap, і при
зменшенні понад ×2 краї мерехтять. Тому:

- запікай **під той розмір, у якому малюватимеш**;
- потрібно два розміри — дві текстури (`.copy`), не один розтягнутий регіон;
- потрібен вільний розмір — це не растр, повертайся до §1–2.

### Коли взагалі запікати, якщо вектор і так різкий?

Тільки в двох випадках:
1. **ефекти** — блюр, маска, будь-який `post` (§4). Вектор їх не вміє;
2. **змішування з іншими текстурами в один батч** — запечена зірка батчиться з
   PNG-іконками сусіднього атласу? Ні, це різні текстури — але вона батчиться
   з іншими `VfxTexture` того ж розміру сторінки? Теж ні. Чесно: батчинг тут
   не аргумент, `AMsdfGroup` дає те саме без пам'яті. Аргумент — лише ефекти.

## 4. Ефекти: блюр, світіння, спільний регіон

```kotlin
val star_glow = VfxTexture(128f, 128f, base = star, shape = effect,
                           post = listOf(BlurEffect(radius = 2f)), density = 1f)
```

`shape` малює фігуру, `post` обробляє результат ланцюгом.

### Блюр: `radius` — це крок, а не сигма. Робіть світіння на `density = 1`

`gaussianBlurFS.glsl` — 9 семплів із фіксованими гаусовими вагами, а
`BlurEffect.radius` — **відстань між семплами в текселях буфера**. Радіус 6 =
дев'ять точок з кроком 6 текселів на відрізку ±24 — між ними дірки, і на
краю з'являються смуги (те саме «кривенько», що видно оком). Плюс 4 проходи
(H, V і дві діагоналі) роблять із цього не гаусс, а «зірку» з чотирьох мазків.

Виміряно на пристрої (шорсткість профілю, менше = гладше):

| варіант | шорсткість |
|---|---|
| `density = 3`, `radius = 6` | 0.50 — смуги |
| `density = 1`, `radius = 2` | **0.00** — гладко |

Правило: **крок ≤ 2 текселі; ширше світіння — нижча `density`, не більший
`radius`.** Світінню роздільність не потрібна, а буфер у 9 разів менший.
Ефекту потрібне місце назовні: `bleed ≈ 9 × radius / density` юнітів, інакше
зріже по краю текстури (див. §6).

Що вартувало б переписати колись: шейдер із σ як параметром, семплами по
одному текселю й лише двома проходами (H + V). Тоді `radius` стане чесним
радіусом. Зараз — правило вище, і воно дає чистий результат.

### Світіння = розмите ПІД різким

```kotlin
at(22f, 150f, Image(msdf.star_glow.region).apply { setSize(128f, 128f); color = ORANGE })
at(22f, 150f, VfxImage(screen, msdf.star, msdf.effect).apply { setSize(128f, 128f); color = GOLD })
```

Той самий квад, той самий розмір — розмита копія лягає точно під різку.
Різка — вектор (`VfxImage`), бо їй ефекти не потрібні, а розмір вільний.

### Один регіон — багато споживачів — одна зміна

```kotlin
at(200f, 150f, Image(msdf.star_glow.region).apply { setSize(128f, 128f); color = CYAN })

// будь-де, будь-коли:
gdxGame.assetsMsdf.star_glow.effect<BlurEffect>()?.radius = 20f
```

Перевірено: два `Image` з `star_glow.region` (помаранчевий і синій) — після
зміни радіуса **обидва** оновились наступним кадром. Регіон один, FBO один,
перемальовування одне. Кадри знято чергою: радіус чергується 6 ↔ 20, яскравість
центру 254 ↔ 167 — це той самий об'єкт міняє вміст під усіма споживачами.

### Незалежний ефект

`.resized()` **ділить** інстанси ефектів — зміна в одній міняє й іншу. Тому й
називається `resized`, а не `copy`: це та сама текстура в іншій роздільності,
а не незалежний клон. Так зроблено навмисно: «змінив блюр раз — оновились
усі розміри» — рівно те, чого хотілось від спільних регіонів.

Треба окремий блюр для окремого місця — новий `VfxTexture` з новим
`BlurEffect(…)` через конструктор. Це один рядок, і він чесно каже, що ефект
інший.

### Анімація параметра щокадру

Можна. Ціна — один прохід FBO **на кадр на текстуру** (не на споживача).
`star_glow` 128 юнітів = 384² px, блюр — 4 проходи. На одну таку — дрібниця;
на десять одночасно — уже помітно. Анімуй радіус зміною, не «на всяк випадок».

## 5. Де створювати і хто звільняє

| де | коли | хто dispose |
|---|---|---|
| `SpriteUtil.Msdf` (поруч із регіонами) | у `GDXGame.create()` через `spriteManager.loadAtlasNow(MSDF)` — `assetsMsdf` доступний з першого екрана, включно з Brand | `VfxTextures.dispose()` в кінці гри |
| поле екрана | у `show()` або пізніше | `disposableSet.add(tex)` — екран сам звільнить |
| поле актора | у `addActorsOnGroup()` | `disposableSet.add(tex)` актора |
| у циклі / в `draw()` | **ніколи** | — кожен виклик = новий FBO |

Конструктор `VfxTexture` GL не чіпає — лише реєструє; перший рендер іде у
`VfxTextures.update()` на початку наступного кадру. Регіон бази має існувати —
для MSDF це гарантовано з `create()`.

Втрата GL-контексту, перехід між екранами — усе автоматично, нічого не робити.

## 6. Поле навколо фігури — малюється назовні

msdfgen з `-autoframe` лишає `PX_RANGE/2` текселів поля з кожного боку: на клітинці
64 фігура займає **56/64 = 87.5 %** регіона. Звичайний `Image(msdf.star)` малює регіон
цілком, і `setSize(64f, 64f)` дає зірку 56.

`AMsdfImage` малює поле **за межами** свого прямокутника (усередині — `OverflowImage`)
— як Figma розширює шар ефектом. Тому `setSize` / `fillParent` / `setScale` / hit-box —
усе про саму фігуру, і числа з макета переносяться без множників:

```kotlin
AMsdfImage(screen, msdf.star).apply { setSize(64f, 64f) }        // зірка рівно 64
```

Винос по осі — `width × (PX_RANGE/2) / (cell − PX_RANGE)`; на несиметричній клітинці
різний по осях, рахується з живого регіона щокадру.

### Несиметричні SVG

Працюють. `gen-msdf.sh` рахує клітинку з `viewBox`: довша сторона = `DIM`, коротша
пропорційно, плюс `PX_RANGE`. Перевірено: 20×64 → 26×64, 200×100 → 64×36, поле 4
текселі з усіх боків. `pack-msdf.py` довільні розміри пакує (полиці за висотою).

Обмеження — роздільність **короткої** сторони: 200×100 при `DIM 64` — це 28 текселів на
100 юнітів. Для великих панелей піднімай `DIM`.

### Запечене: `VfxTexture` і `bleed`

`VfxTexture(w, h, base = msdf.x, shape = msdf.effect)` запікає фігуру **рівно `w×h`**,
край у край: msdf-квад бази розширюється на поле, зайве вилітає за FBO. `Image(tex.region)`
розміром `w×h` накладається на `AMsdfImage` того ж розміру один в один.

Post-ефект (блюр, світіння) потребує місця **назовні** — це `bleed`, на бік, у юнітах:

```kotlin
val glow = VfxTexture(186f, 101f, base = msdf.aaa, shape = msdf.effect,
    post = listOf(BlurEffect(radius = 2f)), density = 1f)      // bleed = 19, порахований сам

glow.image()                                              // шар: межі 186×101, світіння назовні
Image(glow.region).apply { setSize(glow.outerWidth, glow.outerHeight) }  // frame, що обіймає ефект
```

`bleed` **не задаєш** — `VfxTexture` рахує його з ланцюга `post` (`reachTexels() / density`);
подивитись результат — `tex.bleed`. Явне число лише під ефект, чий параметр міняється на
льоту: FBO фіксований, тож став під максимум.

Ширину світіння крутиш через `density`: `radius` лишається 2 (крок понад 2 текселі —
смуги), а `density 1` дає ~19 юнітів назовні, `0.5` → ~37, `2` → ~10.

Те саме для живих акторів — `VfxGroup` з `bleed`: FBO більший, результат малюється зі
зсувом, межі групи й діти — про контент. `ABlurBack` / `AMask` лишаються з `bleed = 0`.

## 7. Пастки, які вже наступили

- **`Image(msdf.x)` замість `AMsdfImage`** — без msdf-шейдера це кольорова каша, а розмір 87.5 %.
- **Ширший блюр через `radius`** — смуги. Ширина — через `density`; `radius` лишається 2.
- **`star_48` на 128** — мило. Не «MSDF зламався», а «це вже растр».
- **`resized()` у `draw()`** — кожен кадр нова текстура. Тільки в поле.
- **PNG всередині `AMsdfGroup`** — каша. Тільки msdf-регіони.
- **Радіус блюру як σ** — ні, це крок між семплами в текселях. Понад 2 — смуги. Ширше = менша `density`.
- **`assetsMsdf` до того, як атлас завантажено** — `lateinit property atlas has not been initialized`.
  Тому атлас вантажиться синхронно в `create()`, раніше за будь-який екран.
- **Змінив блюр «на всяк випадок» щокадру** — 4 проходи FBO на кадр даремно.
