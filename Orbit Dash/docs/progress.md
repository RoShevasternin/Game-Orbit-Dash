# Прогрес і маски: що коли брати

Інструментів стало п'ять, і вони не взаємозамінні. Головне питання одне:
**що саме задає форму** — математика, картинка чи живе піддерево акторів.

## Таблиця вибору

| що треба на екрані | чим | скільки текстур | ціна |
|---|---|---|---|
| смуга-капсула: буст у HUD, шкала, XP | **`ABarProgress`** | 0 | 1 актор, 1 draw, ідеальний край на будь-якому розмірі |
| кільце, що тане: таймер комбо, щит на м'ячі | **`ARingProgress`** | 0 | те саме, але по колу |
| прогрес довільної форми: зірка, хрест, фігура з дірками | **`AMaskProgress`** | 1–3 | 1 draw, форма растрова — масштаб гірший |
| багато однакових масок, усі статичні | **`VfxTexture(base, post = [MaskEffect])`** → `Image(.region)` | 1 на всіх | запікається раз, N копій = 1 draw call |
| маска над ЖИВИМ піддеревом акторів | **`AMask`** (`VfxGroup`) | FBO | перемальовка буфера щокадру, поки діти рухаються |

Правило в одному рядку: **капсула — `ABarProgress`, кільце — `ARingProgress`,
будь-яка інша форма — `AMaskProgress`, ціле піддерево під маскою — `AMask`.**
Останнє коштує найдорожче й береться лише тоді, коли справді треба замаскувати
групу акторів, а не картинку.

## ABarProgress — базовий випадок

```kotlin
val bar = ABarProgress(screen).apply {
    radius     = 1.5f                    // половина висоти = капсула
    trackAlpha = 0.2f                    // 0 — доріжки немає
    fillAlpha  = 1f                      // менше 1 — смуга-привид поверх доріжки
    fillColor.set(boost.info.color)
}
bar.setSize(64f, 3f)
add(bar) { centerX(); bottomToBottom() }

bar.frac = engine.boostFrac              // єдине, що рухається
```

Форму рахує шейдер, тому ассетів нуль, а край лишається чистим і на 64×3, і на
600×40. Радіус більший за половину меншої сторони шейдер клемпить сам — як Figma.

**Картинка замість кольору** — один рядок:

```kotlin
bar.picture = atlas.progress_fill        // текстурний режим вмикається сам
```

Далі два необов'язкові уточнення на `bar.fx`:

- `texturedTrackAlpha = 0.2f` — доріжка тією ж картинкою, пригашеною: видно,
  «що ще проявиться»;
- `textureSlides = true` — картинка не проявляється на місці, а **їде** так, що її
  правий край тримається краю заповнення. Це поведінка «посунути картинку під
  маскою», тільки без маски. З нею доріжку краще лишити кольоровою.

## AMaskProgress — коли форма не капсула

```kotlin
val bar = AMaskProgress(screen, mask = capsuleTex.region)
bar.fill       = atlas.progress_fill     // null → fillColor
bar.track      = atlas.progress_back     // null → trackColor + trackAlpha
bar.trackAlpha = 0.2f
bar.setSize(268f, 25f)

bar.frac = 0.4f
```

Маска — **drawable самого актора**, тобто вона ж і форма. Проста форма печеться без
ассета:

```kotlin
val capsuleTex = VfxTexture(268f, 25f, shape = RoundRectEffect().apply { radius = 10f })
```

Складна приходить картинкою від дизайнера. **Альфа маски керує всім**: дірка
лишається діркою, півпрозоре — півпрозорим.

Напрямок вільний: `fx.axis = Axis.Y` (знизу вгору), `fx.reversed = true` (від
протилежного краю). `fx.slides` працює для всіх чотирьох напрямків.

## ARingProgress — кільце

```kotlin
val ring = ARingProgress(screen).apply {
    trackAlpha = 0.25f                   // 0 — видно лише заповнену дугу
    thickness  = 4f                      // world-юніти
}
ring.setSize(RING_QUAD, RING_QUAD)       // КВАД, не діаметр кільця
ring.radius = 40f                        // радіус осі; null — найбільший, що влазить

ring.frac = engine.comboFrac             // тане від 12-ї за годинниковою
```

`frac = 1` — суцільне кільце без шва: так зроблено кільце щита на м'ячі й хвиля
спалаху (`AWave` успадковує цей актор і жене `radius` з `thickness` у часі).

**Межі актора — квад, а не кільце.** Шейдер малює всередині квада, тому той мусить
умістити радіус + півтовщини + AA: `RING_QUAD = 100` в `ABall` при кільці r 40,
`QUAD = 72` в `AWave` при r до 32. Радіус і товщина — окремі числа в world-юнітах,
не частки розміру, тож усередині групи зі скейлером вони йдуть через
`keepScaled { ring.radius = 40f.toActual }` — як в `ABall`.

Колір беруть **тінтом актора** (`setColorRGB`), а не `ringColor`: `VfxImage` кладе
колір у `v_color`, і доріжка фарбується тим самим множенням. `ringColor` лишається
на випадок, коли доріжка й заповнення мають бути різних кольорів.

## Три пастки, на яких уже обпеклись

**Розмір усередині групи зі скейлером.** У `TestScreen` група без скейлера, тому
`setSize(200f, 8f)` — юніти як є. Усередині групи з `sizeScaler` (як `APanelBooster`)
треба `setSizeScaled(...)`, а радіус — через `keepScaled { bar.radius = (H / 2f).toActual }`.
Інакше при першому розкладі замість капсули буде прямокутник: фактор скейлера існує
лише зі stage, а `sizeChanged()` викликається раніше.

**Текстура має пережити фон.** Регіон з атласу — переживе. `Texture` з `Pixmap`
(як `makeGradient()` на стенді) — ні: після повернення з фону GL-текстура зникає.
У грі — тільки атлас.

**Перевернуті регіони.** `VfxTexture.region` перевернутий по вертикалі (вміст FBO
лежить догори дном). Це вже враховано в `BATCH_VERT` (патч 61), але якщо колись
побачиш перевернуту картинку в новому ефекті, який читає `v_localUV`, — причина
майже напевно тут.

## Скільки це коштує

`VfxImage` ставить шейдер у батч і скидає його назад — це **два флаші на актор**.
Для одиниць смуг байдуже, для сотні — ні. Сто однакових масок роблять не сотнею
акторів, а або запіканням (`VfxTexture` + `Image` ×100 = 1 draw call), або одним
актором із власним `draw()`, який ставить шейдер раз, — як це вже роблять `ABurst`
і `AComet` з частинками.

`AMask` дорожчий за все перелічене: `VfxGroup` тримає власний FBO і перемальовує
його, щойно діти зрушили. У прогресі це кожен кадр, тому для смуг і фігур він не
береться ніколи.

## Де що лежить

Одна родина — одні теки й одна семантика імен: **`<Форма>Progress`**.

| | шлях |
|---|---|
| актори | `game/actors/progress/` — `ABarProgress`, `ARingProgress`, `AMaskProgress` |
| ефекти | `game/utils/vfx/effects/base/progress/` — `BarProgressEffect`, `RingProgressEffect`, `MaskProgressEffect` |
| шейдери | `assets/shader/base/progress/` — `barProgressFS.glsl`, `ringProgressFS.glsl`, `maskProgressFS.glsl` |

Імена читаються однаково: спершу ЧИМ задана форма (`Bar` — математика по прямій,
`Ring` — математика по колу, `Mask` — картинка), потім що це (`Progress`). Четвертий,
якщо колись буде, ляже туди ж і назветься так само.

`OrbitRingEffect` у цю родину НЕ входить і лишається в `effects/` + `shader/orbit/`:
кільця поля — ігрова геометрія, а не будівельний блок UI, і прогресу в них немає.
