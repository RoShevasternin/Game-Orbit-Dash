# Тюнери ефектів

Тюнер — сторінка на claude.ai для калібрування ефекту оком, замість редактора партиклів.
Той самий механізм, що й сторінка-патч (`docs/patches/_page/`): сторінка тримає свій стан
у `<script id="tuner-data">`, кнопка «Готово» публікує його в саму сторінку через
`claude.use("artifact").publish(html)`, а Claude читає його `Artifact read`.

## Як користуватись

1. Відкрити тюнер, крутити повзунки — канвас показує ефект одразу. Кожен повзунок підписаний
   **іменем константи Kotlin** (`AWave.R_TO`, `ABurst.SPEED_MAX`); те, що змінено проти
   патча, підсвічено, а дефолт показано поруч (`53: 32`).
2. «Слоу-мо ×0.25» — щоб роздивитись; «Ще раз» — повторити спіймання; «повторювати» — цикл.
3. У коментар — те, що повзунками не передати («ореол теплішим»).
4. «Готово» → сторінка зафіксована. Написати в чат що завгодно — сповіщення сесію не будить.
5. Claude переносить `state.values` в патч один в один і ставить `state.result` на сторінці.

## Файли

`NN-<назва>.html` — тюнер під патч NN (`53-spark.html` — хвиля, крапки, мікрофриз іскри).
HTML пишеться від руки: канвас рахує ефект **тією самою математикою**, що й актор у грі
(порядок кроків як у `RunEngine.update()`, формули як в `act()`/`draw()`), інакше числа
брехатимуть. Одиниці — юніти поля (320 на ширину), на телефоні 720 px це 2 px/юніт.

## Стан

```json
{ "values": { "HIT_STOP_NEAR": 0.03, "R_TO": 32, "...": 0 },
  "note": "коментар", "submitted": "ISO-дата або null",
  "result": { "ok": true, "note": "у патчі 55" } }
```

`values` після «Готово» — **повна** мапа (і змінені, і дефолтні). До «Готово» незбережені
значення живуть у `localStorage` браузера (`tuner-draft-NN`) і Claude їх не бачить.

## Межа

Канвас у браузері ≠ GPU телефона. Форма, таймінг, кількість, швидкості, кольори — точно,
бо це числа. Блюр і адитивне змішування — приблизно: після патча дивитись на пристрої і
добивати одним коефіцієнтом.
