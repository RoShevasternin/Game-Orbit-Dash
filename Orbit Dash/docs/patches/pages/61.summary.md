## Що і навіщо

Справжня причина перевернутої картинки — **не в `MaskProgressEffect`**, а в спільному
вершинному шейдері `BATCH_VERT`, яким користуються всі ефекти через `VfxImage`.

### Ланцюжок

`VfxTexture.region` **перевернутий по вертикалі**: вміст FBO зберігається догори дном, тому
при створенні стоїть `region.flip(false, true)` (`VfxTexture.kt:212`). Для капсули-маски це
дає `v = 1`, `v2 = 0`, тобто `uvRange.y = −1`.

А в `BATCH_VERT` нормалізація стояла під умовою:

```glsl
v_localUV = (uvRange.x > 0.0 && uvRange.y > 0.0) ? (a_texCoord0 - u_uvMin) / uvRange : a_texCoord0;
```

`−1 > 0` хибне, тож шейдер падав на **запасний шлях** — сирі UV атласу замість нормалізованих.
Для капсули (повний FBO, u 0..1) по горизонталі різниці не видно, а по вертикалі
`v_localUV.y` ставало **1 угорі й 0 унизу**. Заповнення читало картинку з перевернутим Y.

### Чому не помітили раніше

- `ABall`, `AWave`, `ARoundRect`, смуга HUD — усі беруть `drawerUtil.getRegion()`, звичайний
  неперевернутий регіон: `uvRange.y = 1 > 0`, нормалізація працювала.
- Тестова картинка була градієнтом 256×1 — однаковим по вертикалі, перевертання не видно.
- Ламалось лише там, де в `VfxImage` кладуть **регіон із `VfxTexture`** і ефект читає
  `v_localUV`, — тобто рівно в `AMaskProgress` із запеченою маскою.

### Виправлення

Ділення на негативний діапазон працює саме по собі — воно дає правильні 0..1. Перевіряти
треба лише **вироджений** випадок (діапазон нульовий), тому `> 0.0` стає `abs(...) > 0.0`:

```glsl
v_localUV = (abs(uvRange.x) > 0.0 && abs(uvRange.y) > 0.0) ? (a_texCoord0 - u_uvMin) / uvRange : a_texCoord0;
```

Для капсули: верх `(1 − 1) / (−1) = 0`, низ `(0 − 1) / (−1) = 1` — як і має бути.

### Що це ще лагодить

Той самий шлях використовує `textureSlides` у `ProgressBarEffect` (патч 59): зсув теж рахується
від `v_localUV`. З перевернутим регіоном він з'їжджав би так само — просто ми ще не пробували
там `VfxTexture`-регіон.

Зміна одного рядка в спільному коді, тому варто глянути на пристрої й на решту `VfxImage`:
м'яч, хвиля, кнопки. Для них `uvRange.y` додатний, поведінка не змінюється ні на піксель.
