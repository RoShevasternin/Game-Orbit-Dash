# 35 — Пунктир активної орбіти їде за м'ячем, а не проти

## Що і навіщо

Після патча 34 пунктир крутився **проти** м'яча. Причина: у шейдері вісь Y перевернута,
і в патчі 34 це не враховано.

`v_localUV` береться з UV текстури. SpriteBatch дає низу квада `v2 = 1`, а верху `v = 0`.
Тому в `orbitRingFS.glsl` Y іде вниз, і `atan(p.y, p.x)` на екрані росте **за
годинниковою**. Контракт `OrbitRingEffect.dashShift` («росте — проти годинникової»)
виконувався навпаки.

Далі по кроках:
- м'яч їде за годинниковою;
- `ballAngle = -engine.angle` спадає, `delta < 0`, тож `dashShift` теж спадає;
- через перевернуту вісь зменшення `dashShift` на екрані означає рух проти годинникової.

**Як у JSX.** Там `st.dashOff -= v·wdt·0.9`, `ctx.arc(…, 0, 2π)`.
- **Напрям.** У canvas Y іде вниз, дуга малюється за годинниковою, від'ємний offset
  зсуває штрихи вперед. Отже, пунктир іде **в той самий бік, що й м'яч**.
- **Швидкість.** 0.9 px дуги на градус м'яча. На зовнішній орбіті це ≈0.16° на градус
  м'яча, тобто пунктир ~6× повільніший. Швидкість **не стала**: вона пропорційна `v` і
  росте разом із м'ячем (100 → 280°/с), просто на такій малій швидкості це майже не видно.
  `DASH_FOLLOW = 0.45` відтворює рівно це, тож міняємо лише знак.

**Чому в шейдері, а не знаком у `syncFrom`.** Так контракт `dashShift` стає правдою, і
всі кути поля знову в одній системі, де Y іде вгору (як `AOrbitField.positionAt`).
Побічний ефект: у меню пунктир (`DASH_IDLE_SPEED = -25`) тепер теж іде за годинниковою,
як м'яч у грі.

## 1. `orbitRingFS.glsl`

**Файл:** `app/src/main/assets/shader/orbit/orbitRingFS.glsl`, `main()`, блок `// пунктир ЗВЕРХУ`.

**ЗАМІНИТИ**

```glsl
        float turns  = atan(p.y, p.x) / TWO_PI;              // −0.5..0.5 оберту
```

на

```glsl
        // v_localUV — це UV текстури, Y у нього ВНИЗ. Мінус повертає
        // математичний кут (проти годинникової), як в AOrbitField.positionAt
        float turns  = atan(-p.y, p.x) / TWO_PI;             // −0.5..0.5 оберту
```

## Варіант: стала швидкість (не як у JSX)

Якщо хочеш, щоб пунктир не прискорювався разом із м'ячем, зроби це в
`AOrbitField.syncFrom()`.

**ЗАМІНИТИ**

```kotlin
            dashShift += DASH_FOLLOW * delta
```

на

```kotlin
            // Стала швидкість: від м'яча береться лише напрям, на паузі delta = 0 — стоїть
            dashShift += Math.signum(delta) * DASH_RUN_SPEED * Gdx.graphics.deltaTime
```

Також додай константу `DASH_RUN_SPEED` (design-юнітів дуги за секунду) і `import com.badlogic.gdx.Gdx`.
Недолік: дебажний `TIME x0.25` не сповільнює пунктир. Рекомендую лишити як у JSX.

## Перевірка

`./gradlew assembleDebug`, потім на пристрої зроби два знімки з інтервалом 0.25 с.
Штрихи праворуч на кільці мають піти **вниз**, у бік м'яча. На паузі пунктир стоїть.
