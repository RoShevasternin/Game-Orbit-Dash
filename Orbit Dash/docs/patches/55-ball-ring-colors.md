# Патч 55 — Кільце комбо в колір м'яча, кільце щита в колір бустера SHIELD

20.09.2026 · 1 → 2. Компілюється після 1; 2 — лише коментар.

Сторінка: https://claude.ai/artifact/G53qy1JWRVDxAdSSSbZdAw

## Що і навіщо

Кільця над м'ячем досі були білі — шейдер `ProgressRingEffect` малює `u_color` (біле за
замовчуванням), і жоден із двох акторів його не перефарбовував. У прототипі так ніколи не
було: там кільце комбо малюється `p.player` — тим самим кольором, що й тіло м'яча, — а кільце
щита `rgba("#4dd9ff", 0.8)`, тобто кольором бустера SHIELD.

Патч приводить гру до прототипу і розводить два джерела кольору, бо вони означають різне.

### Два джерела, і це навмисно

**Усе, що є сам м'яч, бере `player` із теми.** Тіло й ореол уже так фарбувались; тепер туди ж
ідуть кільце комбо (з доріжкою) і ореоли супутників. Комбо — стан гравця, тож воно й має
мінятись зі скіном: у NEON блакитне, у MAGMA помаранчеве.

**Кільце щита кольору теми не слухає.** `BoostCatalog` уже тримає правило: буст упізнається
лише кольором, тому колір буста — константа, а не оформлення. Щит блакитний `#4DD9FF` у
будь-якій темі, і кільце над м'ячем — те саме повідомлення, що й шестикутник, який ти підібрав.

### Що лишається білим

Крапка напряму, крапки супутників, іскра на полі (`ASpark`), хвиля спалаху (`AWave`). Іскра
біла в будь-якій темі — так у Figma; а коли її спіймано, вона стає супутником: крапка та сама,
але ореол уже в кольорі гравця. На полі іскра нічия, на орбіті — твоя.

### Чому тінт актора, а не `fx.color`

`progressRingFS` віддає `vec4(u_color, a) * v_color`, а `VfxImage` кладе колір групи у
`v_color`. Тому `setColorRGB` на акторі фарбує і дугу, і доріжку одним множенням — тим самим
механізмом, яким уже фарбуються `aGlow` і `aBall`. Через `fx.color` довелось би тримати колір
у двох різних місцях і не можна було б задати альфу щита (u_color — vec3).

Зібрано в лабораторії: `assembleDebug` — BUILD SUCCESSFUL.

## 1. `app/src/main/java/com/lewydo/orbitdash/game/actors/objects/ABall.kt`

### 1.1 — ДОДАТИ два імпорти

Перед `import com.lewydo.orbitdash.game.utils.GameColor`:

```kotlin
import com.lewydo.orbitdash.engine.RunEngine.Boost

```

### 1.2 — ДОДАТИ абзац у шапку класу

Після абзацу «Кільця — один шейдер ProgressRingEffect…»:

```kotlin
//
//  КОЛЬОРИ — З ДВОХ РІЗНИХ ДЖЕРЕЛ, І ЦЕ НАВМИСНО. Усе, що є САМ м'яч — тіло,
//  ореол, кільце комбо, ореоли супутників — бере player із теми: комбо це стан
//  гравця, тож воно й міняється зі скіном. Кільце щита читає колір бустера
//  SHIELD із BoostCatalog і в темі не бере участі: щит упізнається лише
//  кольором, і блакитне означає «щит» у будь-якій темі (див. шапку каталогу).
//  Білими лишаються крапка напряму й крапки супутників — як іскра на полі.
```

### 1.3 — ДОДАТИ константу в `companion object`, секція «кільце щита»

Після `private const val SHIELD_W = 2.5f`:

```kotlin
        /** Прозорість кільця щита, як у прототипі: rgba("#4dd9ff", 0.8). */
        private const val SHIELD_A = 0.8f
```

### 1.4 — ЗАМІНИТИ `addShield()`

Було:

```kotlin
    private fun addShield() {
        add(aShield) { size(RING_QUAD); center() }
        aShield.isVisible = false
    }
```

Стало:

```kotlin
    private fun addShield() {
        add(aShield) { size(RING_QUAD); center() }
        aShield.setColorRGB(Boost.SHIELD.info.color)
        aShield.color.a = SHIELD_A
        aShield.isVisible = false
    }
```

Колір щита ставиться **один раз**, а не в `syncTheme()`: він сталий, теми не слухає.

### 1.5 — ЗАМІНИТИ `syncTheme()`

Було:

```kotlin
    private fun syncTheme() {
        aGlow.setColorRGB(ThemeManager.current.player)
        aBall.setColorRGB(ThemeManager.current.player)
    }
```

Стало:

```kotlin
    private fun syncTheme() {
        val player = ThemeManager.current.player
        aGlow.setColorRGB(player)
        aBall.setColorRGB(player)
        // Кільце комбо — тінт актора, не fx.color: VfxImage віддає color у
        // v_color, і доріжка (trackAlpha) фарбується тим самим множенням.
        aCombo.setColorRGB(player)
        for (s in sats) s.aGlow.setColorRGB(player)
    }
```
