# `VfxTexture`: запікати фігуру край-у-край, без поля

## Що і навіщо

`drawBase` кладе **весь регіон** на **весь FBO**, тож поле autoframe запікається
всередину: у текстурі 186×101 фігура займає 163×80, решта — порожнеча. Це та сама
задача, що `MsdfInner` вирішив на екрані, і розв'язок той самий — **малювати квад
більшим за FBO**, щоб поле вилізло за межі й обрізалось, а у текстуру потрапила
сама фігура.

Різниця з екраном лише в тому, куди дівається поле: там воно малюється й видиме,
тут — відрізається viewport'ом.

**Чи не з'їсть це згладжування.** Ні. Контур торкається меж свого bbox лише в
чотирьох крайніх точках, і там він паралельний межі — обрізати нічого. На всіх
кривих і діагоналях контур усередині FBO, і повний спад альфи на місці. Це те саме,
що робить будь-який експорт PNG із Figma: фігура рівно в свій bbox.

Після зміни `VfxTexture(186f, 101f, base = aaa, shape = effect)` дає **фігуру
рівно 186×101**, і `Image(tex.region).setSize(186f, 101f)` збігається з
`AMsdfImage` того ж розміру.

## `utils/vfx/VfxTexture.kt`

### 1. ДОДАТИ імпорт

```kotlin
import com.lewydo.orbitdash.game.utils.vfx.effects.base.MsdfShapeEffect
```

### 2. ЗАМІНИТИ рядок малювання у `drawBase()`

**Було:**

```kotlin
        sb.draw(src, 0f, 0f, width, height)
```

**Стало:**

```kotlin
        // MSDF-регіон несе поле pxRange/2 текселів з кожного боку. Малюємо квад
        // БІЛЬШИМ за FBO рівно на це поле: воно вилітає за viewport і обрізається,
        // а в текстуру лягає сама фігура, край у край. Те саме, що MsdfInner
        // робить на екрані; без цього у 186×101 запеклася б фігура 163×80.
        // Множник по осях різний — клітинка може бути несиметричною (64×39).
        val px = if (base == null) 0f else (fx as? MsdfShapeEffect)?.pxRange ?: 0f
        if (px > 0f) {
            val mx = width  * 0.5f * px / (src.regionWidth  - px)
            val my = height * 0.5f * px / (src.regionHeight - px)
            sb.draw(src, -mx, -my, width + mx * 2f, height + my * 2f)
        } else {
            sb.draw(src, 0f, 0f, width, height)
        }
```

`as?` тут навмисно: поле — властивість саме msdf-регіонів, і решта `shape`-ефектів
(`RoundRectEffect`) малюють свою фігуру в повний квад, їм розширювати нічого.

## Перевірка

`./gradlew assembleDebug`, потім стенд: `Image(msdf.aaaTexture)` і `AMsdfImage`
з тим самим `setSize(186f, 101f)` мають накластись край у край. Запечена буде
трохи м'якша — це растр 558×303 px проти вектора.

## Межа, про яку треба знати

З `post`-ефектами (блюр, світіння) фігура тепер займає **весь** FBO, і блюру нема
куди розпливтися — його зріже на межі текстури. Тому для світіння лишається старий
рецепт: брати текстуру більшу за фігуру. Зараз у грі жодного запеченого світіння
немає (світіння — PNG `item_glow`), тож питання відкладене; коли дійде — це той
самий пункт із `decisions.md` §7: окремий атлас із `-apxrange -24 4`, `DIM 128`.

## Заразом: не губи об'єкт

```kotlin
val aaaTexture = VfxTexture(186f, 101f, aaa, effect).region
```

`.region` узято одразу, сам `VfxTexture` не збережено — не викликати `invalidate()`,
не змінити ефект, не `dispose()`. Тримай поле:

```kotlin
val aaaBaked   = VfxTexture(186f, 101f, base = aaa, shape = effect)
val aaaTexture = aaaBaked.region
```
