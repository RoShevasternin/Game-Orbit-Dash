# 22в — Де вантажити MSDF і де має жити `VfxTexture`

## Заміряно, перш ніж вирішувати

Що насправді лежить на чорному екрані `GDXGame.create()`:

| що | диск | GPU | коли |
|---|---|---|---|
| `atlas/msdf.png` + `.atlas` | **3 КБ** | 0.03 МБ | `loadAtlasNow(MSDF)`, блокуюче |
| `MsdfManager()` — 3 шрифти | **1.35 МБ** (3 PNG 880² + 3 JSON по 43 КБ) | **8.90 МБ** | eager у конструкторі `MsdfFont` |
| `MsdfManager()` — 4 шейдери | — | — | eager, 4 компіляції GLSL |
| 4 `VfxTexture` (`circle`, `gem`, `glow`, `glowOrbit`) | — | — | **не тут**: конструктор GL не чіпає |

Тобто інтуїція правильна, але вказує не на той ассет. **MSDF-атлас — 3 КБ, він не тримає
нічого.** Чорний екран тримають **шрифти**: `MsdfFont.init` одразу парсить JSON і створює
`Texture`, а `MsdfManager` створює всі три шрифти й чотири шейдери в конструкторі, у тому ж
`create()`.

Друге, важливе для «багато VfxTexture — може зайняти довго»: **`VfxTexture` не пече себе в
`create()`**. Конструктор лише реєструється в `VfxTextures`; FBO створюється й малюється у
`VfxTextures.update()` на початку **першого кадру першого екрана**. Отже зростання кількості
текстур не додає до чорного екрана взагалі — воно додає до першого кадру Brand/Loader, тобто
дасть хітч (клац), а не чорноту. Сьогодні їх чотири й пікінг — сотні мікросекунд.

## 1. Атлас MSDF → у `LoaderScreen.loadSplashAssets()`

Можна і варто — не заради сьогоднішніх 3 КБ, а щоб воно вже лежало в правильному місці,
коли атлас виросте.

Чому це безпечно саме там: у `LoaderScreen.show()` порядок уже правильний —

```kotlin
rootConstraintLayout.color.a = 0f
loadSplashAssets()      // ← атлас тут
super.show()            // ← і лише тут створюються актори лоадера
```

а актори лоадера msdf потребують (`AOrbitEmblem` → `assetsMsdf.glowOrbit`, `ABallDecor`/
`AGemDecor` → `circle`/`gem`/`glow`, `AComet` → `glow`).

Перевірено: у release перший екран — `BrandScreen`, і він `assetsMsdf` не торкається
взагалі (`ABrandGroup` і `ABrandLogo` беруть усе з `assetsBrand`). Якщо колись знадобиться —
`loadAtlasNow` можна кликати повторно: `AssetManager` рахує посилання, другий виклик
віддасть той самий атлас.

### `GDXGame.kt`, `create()` — ЗАМІНИТИ

```kotlin
        // MSDF-атлас потрібен усім екранам, включно з Brand, важить кілобайти й ні
        // від чого не залежить — вантажимо синхронно тут. Далі assetsMsdf доступний
        // із першого кадру. (loadAssets() лоадера підхопить його ще раз — дедуплікується.)
        spriteManager.loadAtlasNow(SpriteManager.EnumAtlas.MSDF)
        assetsMsdf
```
**на**
```kotlin
        // Ассети тут не вантажимо: create() — чорний екран без жодного кадру.
        // Усе, що читається з диска, робить LoaderScreen — там є прогрес і зорі.
```

### `LoaderScreen.kt`, `loadSplashAssets()` — ЗАМІНИТИ

```kotlin
        // Порожньо: сплешу більше нічого не треба — MSDF-атлас уже завантажений
        // синхронно в GDXGame.create(), а світіння орбіт — VfxTexture, не PNG.
```
**на**
```kotlin
        // MSDF-атлас — синхронно і ПЕРШИМ: усі актори лоадера (емблема, комета)
        // беруть із нього фігури, а створюються вони нижче, у super.show().
        // loadAtlasNow перезаписує loadableAtlasList, тому кличемо його до
        // loadAssets(), поки в черзі нічого не чекає.
        gdxGame.spriteManager.loadAtlasNow(SpriteManager.EnumAtlas.MSDF)
        gdxGame.assetsMsdf
```

**Пастка:** якщо в DEBUG заходити напряму в `TestScreen` (він теж читає `assetsMsdf`), атлас
має бути завантажений — при старті через `LoaderScreen` це так.

## 2. Шрифти — головний виграш, але окремим кроком

`MsdfManager` створюється в `create()` і живе рівно стілько ж, скільки `GDXGame` (диспозиться
в його `dispose()`). Тому `by lazy` на його полях **безпечний** — це не `object`, історія
патча 20 (`No buffer allocated!`) сюда не тягнеться.

Але «ліниво» саме по собі лише переносить паузу на того, хто перший намалює текст. Тому
правильна пара:

1. `MsdfManager`: `val fontInter_Medium by lazy { MsdfFont(...) }` (і так само решта двох +
   чотири шейдери);
2. у `LoaderScreen.loadSplashAssets()` або в `loadingAssets()` — **форсити** ті шрифти, які
   потрібні лоадеру, щоб пауза лягла під прогрес-бар, а не під перший `AMsdfLabel`.

Скільки це дає: 1.35 МБ читання з диска і 8.9 МБ GPU їдуть з чорного екрана на екран із
зорями. Перевірити, які шрифти справді потрібні лоадеру (`AMainLoader` → `MsdfStyle`), і
рештa підтягнеться сама при першому використанні.

Це окремий патч — його варто робити після заміру `Gdx.app.log` на пристрої: скільки саме
мілісекунд коштує `MsdfManager()` на Redmi. Без заміру це вгадування.

## 3. Коли `VfxTexture` стане багато — бюджет на кадр

Не зараз: чотири текстури печуться швидше, ніж триває анімація появи екрана.

Тригер: коли перший кадр екрана почне «клацати» (update > ~8 мс) або коли великих текстур
стане з десяток. Лікується **в одному місці** — `VfxTextures.update()`:

```kotlin
    /** Скільки текстур максимум пекти за кадр. 0 = без обмежень. */
    var bakeBudget = 0

    fun update() {
        var baked = 0
        for (i in all.indices) {
            if (bakeBudget > 0 && baked >= bakeBudget) return
            if (all[i].update()) baked++     // update() має вертати true, якщо реально пік
        }
    }
```

Ніде в місцях виклику нічого не змінюється. Заодно лоадер може не завершуватись, поки є
непечені, — тоді «логічне завантаження», а не хітч на першому кадрі.

## 4. Друге питання: `VfxTexture` з MSDF-регіона, але в `All` чи в екрані

**Джерело й холдер — незалежні.** Нічого не змушує тримати текстуру там, звідки її база:
у конструктор передаєш `gdxGame.assetsMsdf.<region>` і `gdxGame.assetsMsdf.effect`, а сам
об'єкт живе де хочеш.

**Холдер вибирається за ЖИТТЯМ, не за джерелом:**

| скільки живе | де оголошувати | хто диспозить |
|---|---|---|
| усі екрани, до кінця гри | `SpriteUtil.Msdf` / `All` | `VfxTextures.dispose()` з `GDXGame.dispose()` |
| один екран | поле екрана + `disposableSet.add(it)` | `AdvancedScreen.dispose()` |
| один актор/група | поле групи + `disposableSet.add(it)` | `AdvancedGroup.dispose()` |

Екранний варіант:

```kotlin
class GameScreen : AdvancedScreen() {

    // Живе рівно як екран: пече себе на першому кадрі, помирає з dispose() екрана.
    // База й effect — спільні з msdf-атласу; холдер тут ні до чого.
    private val aGlowBigTex = VfxTexture(
        200f, 200f,
        base  = gdxGame.assetsMsdf.circle_msdf,
        shape = gdxGame.assetsMsdf.effect,
        post  = listOf(BlurEffect(blur = 60f)),
    ).also { disposableSet.add(it) }
```

**Чому `disposableSet` обов'язковий:** `VfxTexture` реєструє себе в глобальному
`VfxTextures` у конструкторі, а знімається з реєстру лише у своєму `dispose()`. Забув —
текстура й її FBO лишаються в пам'яті після виходу з екрана, і кожен повторний захід
додає ще одну.

**Що перевикористати, а що ні:**

- `effect` — **спільний** `MsdfShapeEffect` із `Msdf`: юніформи в нього однакові на весь
  атлас, новий екземпляр не дає нічого;
- розмір і `density` — **константи**, не з `width` актора: порахований двічі дасть
  `21.9998` і `22.0001`, тобто дві текстури замість однієї (`docs/vfx.md`);
- `bleed` не задавати — порахується з ланцюга `post`; вручну лише коли параметр ефекту
  міняється на льоту.

**Один кадр порожнечі:** текстура, створена в полі екрана, спечеться у `VfxTextures.update()`
наступного кадру — до того `Image` малює прозорий 1×1. Для екрана, що з'являється через
`animShow` з альфи 0, це не видно; якщо колись буде видно — лікується `isVisible = false`
до першого пікінгу, як `syncPlayer` у `GameScreen`.
